# PublicOpinionForecast：项目整体闭环与交付

## 项目定位与验收边界

这是基于 MiroFish 扩展的本地舆情预测研究应用。主线以事件为中心：

**观测与背景 → 图谱及角色 → 仿真 → 冻结预测 → 后续真实观测 → 误差检验 → 滚动校准 → 新材料与新推演 → 综合报告。**

系统还支持明确标注的免费数值基线，便于没有模型凭据时验证数据、界面和交付流程。数值基线、合成数据、历史回放、外部服务替身测试都不会被标记为真实多智能体实测。

软件流程已集成，并使用真实模型和 Zep 完成过一次受控的小规模联调。联调确认接口、模拟和报告可以衔接，不代表前瞻预测质量已经得到验证；不能用测试通过率代替预测准确率，也不能用一个主观完成度分数保证答辩结果。

## 启动与第一遍体验

在项目根目录安装锁文件中的依赖后运行：

```powershell
npm run doctor
npm run dev:research
```

打开 http://127.0.0.1:3000/ ，选择“体验完整合成流程”。进入事件后，按顺序点击“释放下一桶历史观测”，接收 6 桶后生成综合报告。报告可下载为 Markdown、HTML 和 JSON。HTML 可在浏览器打印为 PDF。

如果希望测试前后端同源的交付方式：

```powershell
npm run build
npm run serve:research
```

打开 http://127.0.0.1:5001/ 。使用前请停止占用 5001 端口的另一个项目后端。研究模式明确禁止模型、云图谱及其他原生付费接口，研究接口和前端页面仍可访问。

## 真实事件的操作顺序

1. 准备连续观测 CSV 或 JSON。必填 `timestamp`、`volume`，可选 `negative_ratio`。时间必须带时区，表示每桶结束时刻。至少 3 个早期桶；来源、平台、采样范围、桶长在全程保持一致。
2. 首页创建事件，指定观测截止时间、桶长、未来预测桶数，以及截止前已知的主体和事实。也可以选择已有案例。历史检验允许保存未来留出数据，但生成种子材料只读取截止前信息。
3. 在本地 `.env` 配置模型与 Zep，运行 `npm run dev`。从事件内点击“创建图谱与推演”。平台自动绑定事件案例，进入原生图谱、角色准备、运行和语义报告页面；页面顶部可以返回所属事件。背景材料质量仍需研究者核验，程序无法识别全部人为写入的未来信息。
4. 回到事件，选择本事件、当前观测窗口内的已完成仿真。冻结预测并选择数量映射。原始行为数量与现实平台全量并不等价；早期锚定映射只表示同口径相对热度。系统要求仿真覆盖完整预测窗口，不接受失败、运行中或截短的结果冒充完整预测。
5. 按桶录入新观测、导入批量 CSV/JSON，或在历史回放模式顺序释放留出数据。系统先评分已发出的旧预测，再生成下一版本，保留版本、来源与指纹。历史回放只说明历史样本表现。
6. 查看版本曲线、基线比较及校准原因。新增事实可随观测登记。需要更新语义推演时，先“生成下一轮材料”，再在新窗口建立独立图谱与仿真，随后接入新的参考预测。旧图谱、版本、运行和报告保留。
7. 生成综合报告。报告统一列出数据来源、是否真实/合成、仿真状态、冻结结果、静态与滚动误差、同信息基线、Token 与费用、校准记录和匹配本次运行的语义报告。证据更新后，历史报告标记“已有新证据”，旧报告内容不变。

原始帖子聚合、独立案例、原生自由推演和高级滚动工具仍可从导航访问。事件工作台负责主流程，不要求手工复制案例、仿真和滚动任务的内部编号。

## 三项研究改进与整合

| 内容 | 实现与限制 |
| --- | --- |
| 预测结果验证 | 冻结结果、时间对齐、防止提前使用留出数据、MAE/RMSE/WAPE 等指标、同信息简单基线；没有后续观测就不展示虚构分数 |
| 降本提速 | 准备阶段复用、独立任务并行、仿真时长对齐、SDK 请求及 Token 账本、缓存 Token 与可配置单价；不承诺固定节省百分比 |
| 反馈与滚动更新 | 先评分后更新，有界残差候选、同信息基线回退、版本记录、背景更新与独立新推演；数字校准不新增模型请求，不保证每个事件都改善 |
| 事件主线 | 自动关联材料、项目、运行、冻结、观测、滚动和报告，支持刷新与重新读取已持久化记录 |
| 统一成果 | 无额外模型请求的证据综合报告、原生语义报告的数值附录、MD/HTML/JSON 导出及证据更新提醒 |
| 本地交付 | 独立环境、环境检查、单源 SPA/API、构建本地代码的 Docker、备份恢复、无密钥 CI 验证 |

金额必须先配置正确模型单价。未知价格显示为未知；请求数限制在 SDK 请求边界执行；金额阈值是带并发在途请求误差的软限制。Zep 单独收费，不包含在模型账本金额里。效果与实际耗时必须在同数据、同模型、同预算口径下实测比较。

## 部署与持久化

```powershell
docker compose up --build
```

Compose 从本仓库构建前端和 Python 后端，默认以研究模式运行，地址 http://127.0.0.1:5001/ 。项目数据映射到 `backend/uploads/`，不会因为重建镜像而丢失。启用在线功能时在 `.env` 填写原有模型/Zep 配置，并设置 `MIROFISH_RESEARCH_ONLY=0` 后重新创建服务。

当前开发机器没有 Docker，已验证的是原生同源服务。仓库 CI 包含镜像构建、首页/研究 API 与研究模式拦截检查；以 CI 的实际运行结果为准，不能把配置文件存在当作镜像实测完成。

本部署面向单机毕设与研究演示，不包含互联网多用户运营所需的账号体系与云基础设施。并发约束和数据锁按单个应用进程设计；不要用多个 Web worker 同时写同一份研究目录。

## 备份与恢复

先停止写入中的任务及后端服务，随后在项目根目录执行：

```powershell
npm run backup -- --output backups/forecast.backup.zip
npm run backup -- --restore backups/forecast.backup.zip --destination backups/restored-uploads
```

相对路径以**项目根目录**为基准。备份仅打包本地 uploads：JSON 验证，SQLite 使用数据库备份接口，清单记录文件大小与 SHA-256。排除密钥文件、隐藏文件和数据库临时日志；恢复前验证整个压缩包，拒绝路径越界和覆盖已有目标。

恢复后检查新目录，再在停服状态下自行切换为 `backend/uploads/`。归档可能包含研究材料或帖子，按实际来源要求保管，默认不会提交到 GitHub。云端 Zep 图谱、模型凭据、内存中的角色状态不会被本地备份复原。

服务重启后，磁盘中的事件、预测和报告可重新读取。如果发现此前的运行记录但当前管理器没有对应进程，工作台标记为 `unmanaged`，提示核查旧进程并建立独立重试窗口。系统不自动重跑付费请求，也不声称已经从未保存的检查点恢复仿真。

`npm run verify` 也运行上游仓库维护脚本测试。Windows 未授予符号链接权限时，仅跳过确实无法创建符号链接的两项测试；输入格式和数值边界仍单独执行，Linux CI 执行完整检查。
