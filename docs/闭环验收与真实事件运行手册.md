# 三项扩展的闭环与真实事件运行手册

完整项目现在以首页事件工作台为主入口，自动关联原生推演和三项扩展，并提供统一综合报告。第一次使用请先看 [项目整体闭环与交付](项目整体闭环与交付.md)。本手册保留高级研究工具的独立操作说明。

本项目基于 MiroFish 原始提交 `7657031` 扩展。三个方向分别是预测验证、准备阶段降本提速、真实观测驱动的滚动自适应预测。保留原项目署名与 AGPL-3.0 许可证。

这里的“可运行”和“真实预测效果已经验证”分别验收。当前工程可以接收真实事件数据、形成有版本的预测、接收新观测、评估并更新；没有把测试数量或功能完成度当作真实预测可靠性百分比。

## 直接使用

在项目根目录执行：

```powershell
npm run doctor
npm run dev:research
```

打开 <http://127.0.0.1:3000/research/rolling>。不需要模型或 Zep 凭据，可完成数据准备、合成示例、真实样本的本地历史回放、自动数值纠偏、评分、版本冻结、导出与恢复。此模式关闭模型和云图谱操作。

已有页面：

| 入口 | 用途 |
| --- | --- |
| `/research` | 案例、冻结预测、真实结果验证、对照、费用账本、预算与运行计划 |
| `/research/rolling` | 滚动任务、新观测接收、自适应校准、版本对比、新推演接入 |
| 滚动页“真实数据准备” | 原始帖子去重、时间桶聚合、来源记录 |
| 滚动页“运行检查” | 检查凭据是否配置、运行模式和案例来源完整性；不发出付费请求 |

需要完整多智能体推演时，后续在根目录 `.env` 填好现有的模型和 Zep 配置，再停止离线服务并执行 `npm run dev`。`npm run doctor -- --require-live` 只检查配置是否齐备，不验证凭据有效性和余额。示例占位密钥不能通过检查。可选 BOOST 配置在模板中默认注释，避免复制模板后误用占位配置。

## 真实事件的完整操作流程

1. **统一观测口径。** 明确平台、关键词、帖子 / 评论范围、采样方式、已知遗漏和统计时区。记录来源名称、链接及必要的采集说明。
2. **整理早期材料。** 准备至少 3 个连续、完整观测的时间桶。`timestamp` 表示桶结束时刻，必须带时区。背景材料应包含截止前已知主体和事实，数量数据本身不足以建立有意义的语义角色。
3. **创建研究案例。** 在验证模块导入数据，固定截止时间、桶长、预测窗口与作息时区。系统将后续真实值与早期材料隔离。早期输入和已提交真值不能覆盖，修订需新建案例。
4. **生成初始推演。** 完整模式中用案例的早期材料创建项目，构建独立图谱，准备并运行仿真。研究实例的仿真时长固定为预测窗口；轮长调整为桶长的约数，避免一轮跨多个桶造成伪零值。
5. **检查轮次与费用约束。** 研究窗口需要的轮数会记录在运行计划中。若页面的 `max_rounds` 低于所需轮数，启动前直接拒绝。请缩短窗口或调整轮次，不会把短跑包装成完整预测。先配置 SDK 请求上限和实际模型单价。
6. **冻结初始预测。** 从实际成功运行的日志提取发帖和评论计数，或导入已有外部预测。明确选择原始计数或早期锚定；外部预测的生成过程仍需自行核验。
7. **创建滚动任务。** 选择案例与冻结预测，真实使用选择“实际接收新增数据”；历史实验选择“历史回放”。策略在任务创建时固定。
8. **接收新增真实观测。** 可逐桶输入、上传连续 CSV/JSON，或监听本地采集文件夹。每批数据先使用之前已发出的预测评分，再发行一个新的版本。可附加新近发生的事实和来源说明，供下一轮语义推演使用。
9. **自动检验与纠偏。** 系统检测持续同向偏差，检验此前候选预测的实际误差，并据此决定使用参考曲线、有界残差校准、最近值回退或均值回退。每次决策记录原因和参数。
10. **必要时更新语义推演。** 点击“生成本轮已知材料案例”，只导出已接收观测和当时已知背景。使用新项目、独立图谱运行并冻结后，输入新预测 ID 接回滚动任务。系统检查观测、来源、背景、桶长和预测窗口一致性；旧版本继续保存。
11. **验证和留档。** 可把任一滚动版本冻结进预测验证模块。此后收到的真实观测自动供该版本评分，只有完整窗口到齐才给完整结果。导出逐桶 CSV 与任务 JSON 备份，记录关联模型用量。

研究仿真的日内活动时钟从真实截止时刻开始，默认按 UTC+8 作息；其他场景应在来源设置中填写相应的整数 UTC 偏移。该时区用于日内活动，不改变用于对齐和评分的 UTC 时间戳。

## 第三个创新点的实现范围

当前实现是**数量预测层的误差反馈与自适应校准**。它自动更新未来发帖 / 评论量曲线，不自动编造新事件、情感标签或角色内心状态，也不声称修改了一次已经发出的预测。

每个新观测包含：实际值、接收时间、当时对应的预测版本、预测提前量、未校准值、影子残差候选值、两个同信息基线及实际采用值。

默认策略：

| 参数 | 默认值 |
| --- | --- |
| 最近误差窗口 | 6 个已评分桶 |
| 最少误差样本 | 3 个 |
| 同向偏差持续长度 | 2 桶 |
| 单桶相对偏差触发阈值 | 0.35，分母为 `max(实际量, 参考量, 1)` |
| 候选历史 MAE 改进门槛 | 相对参考曲线至少降低 5% |
| 增益最大范围 | 1/4～4，经样本量收缩 |
| 远期校准衰减 | 每增加一个提前桶乘 0.85 |

残差候选使用已经收到的误差估计加权增益和偏置，并做收缩、非负限制和远期衰减。候选在未启用时也记录“影子预测”，等真实值到达后才评价。启用决策比较的是这些**此前已经计算出的预测**，不能用本桶真实值拟合后再回头给本桶评分。

达到持续偏差和样本门槛后，使用最近窗口内历史 MAE 更低且通过改进门槛的候选；其中包含最近值和均值回退。因此“自适应方案”优于参考曲线不等于“残差方法单独有效”，报告将残差候选和同信息基线分开列出。门槛只提供历史证据，不保证下一桶必然改进。

数值校准的新增模型请求为零。更换语义推演参考后，旧误差单独归档，新参考重新积累校准样本，历史总评分仍保留。

原参考曲线覆盖结束后，参考值采用末值持平外推，并明确标记外推桶数。长时间、新事实较多或持续无法校准时，应生成新的语义推演。系统不会把本地外推称为新一轮多智能体推理。

## 真实数据准备

标准时间桶格式沿用 [研究验证与降本说明](./研究验证与降本说明.md)。新原始帖子格式：

```csv
id,created_at,platform,negative_label
post-1,2026-01-01T08:10:00+08:00,example,1
post-2,2026-01-01T09:20:00+08:00,example,0
```

`id` 与 `created_at` 必填。同平台按稳定帖子 ID 去重；重复 ID 的时间或标注冲突会被拒绝。`negative_label` 可为空，只有一个非空桶中所有记录都明确标注时才计算负面占比。谣言标签不能冒充负面情感标签。

原始聚合区间为 `[开始时间, 结束时间)`。只有使用者确认采集在其**声明的采样范围内完整**，才能将没有记录的桶补零；这不等于整个社交平台没有讨论。

单次文件上限 10 MB，原始帖子最多 100000 条，标准时间桶最多 10000 行。新增观测单批最多 500 桶，必须紧接上次截止时间。批量提交只更新一次，反馈频率低于逐桶接收，不会虚构批次中途的预测。

接入自己现有的本地采集程序时，可让它定期输出标准时间桶 CSV/JSON，再执行：

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 scripts\watch_observations.py --session rolling_替换为实际ID --folder C:\你的采集输出目录 --once
# 去掉 --once 则持续监听；Ctrl+C 停止，不删除原始文件。
```

建议按时间命名文件。监听器只读取文件，使用内容哈希及幂等请求记录避免重启后重复接收；缺桶或冲突文件会报告错误，后续可补齐后重试。它不采集外部网站、不使用模型，也不代替采集合法性和来源质量核验。

## 数据泄漏、版本与恢复

- 创建任务时只读取早期观测和已冻结预测，不读取案例的隐藏真值。
- 历史回放显式逐桶释放真值，标记为回放。实际接收模式拒绝尚未结束的桶。
- 前瞻标签要求系统发行预测的时间早于目标桶结束时间；它证明系统记录的时间顺序，不证明使用者提供的实际值一定真实。
- 没有事先发出预测覆盖的桶计入“未评分”，不补造预测。评估还按提前桶数分层，避免混淆一步与多步预测。
- 新增背景从接收后的版本起可用。导出历史版本时不会夹带后来收到的背景。
- SQLite 事务、修订号与幂等请求 ID 防止并发重复或覆盖。任务内容指纹和预测版本哈希链用于发现修改，不是第三方可信时间戳。
- JSON 备份包含任务观测、版本、策略、背景更新、评分和来源。恢复为暂停的历史回放任务，避免把外部导入文件自动视作本机前瞻证据。
- 备份不恢复第三方图谱、模型凭据、进程或独立费用数据库；旧发布记录保留为历史引用，需要时可在新环境重新发布。
- 单任务最多 1000 个版本、10000 个观测桶、8 MB 持久化任务内容；达到上限后先导出，再建立接续任务。备份使用紧凑 JSON，便于在 10 MB 文件上限内恢复。

历史著名事件还存在模型预训练知识泄漏的风险。仅隔离系统输入不足以证明模型不知道后续，应补充新事件的前瞻实验或匿名化等控制方案。

## 已加入的公开真实样本

来源为 Zubiaga 等发布的 [PHEME rumours and non-rumours](https://doi.org/10.6084/m9.figshare.4010619.v1)，下载地址和完整性校验见 [来源清单](./datasets/pheme/source.json)。Figshare 元数据标注 CC BY 4.0。仓库只保留匿名小时计数，不分发帖子正文、用户信息或单条帖子 ID。

五个历史事件的 CSV 已放在 `docs/datasets/pheme/`，本机也已导入对应验证案例和免费起始参考。它们统计固定对话样本中的源帖和回复，不能当作全平台总量。采样覆盖和去重数量均记录在清单中。

统一实验协议：各事件从首个源帖所在小时起聚合 72 小时，前 12 小时为早期观测，之后 48 小时逐桶回放；初始参考是近 3 桶均值。使用固定默认校准策略，没有根据这五个结果调参。

| 事件 | 自适应 MAE | 固定参考 MAE | 同信息最近值 MAE | 同信息均值 MAE |
| --- | ---: | ---: | ---: | ---: |
| charliehebdo | 204.76 | 368.42 | 183.62 | 252.51 |
| ferguson | 19.91 | 38.51 | 18.94 | 20.90 |
| germanwings-crash | 11.57 | 14.22 | 15.40 | 14.88 |
| ottawashooting | 35.82 | 542.75 | 9.79 | 23.10 |
| sydneysiege | 108.06 | 996.06 | 88.10 | 100.42 |

这里自适应方案在五个事件上优于固定参考，但四个事件不如同信息最近值。结果支持管道和自适应数值层可运行，不能证明方案普遍更优。没有运行 LLM 多智能体，也不能据此声称原版或改进版 MiroFish 的真实预测准确率。

完整指标、策略、实现文件指纹、各方法采用次数和耗时见 [真实样本回放结果](./benchmarks/pheme-rolling.json)。复现命令：

```powershell
cd backend
.\.venv\Scripts\python.exe -X utf8 scripts\prepare_pheme.py --archive uploads\public-data\pheme-rnr-dataset.tar.bz2 --output ..\docs\datasets\pheme --benchmark ..\docs\benchmarks\pheme-rolling.json
```

原始归档来自 `https://ndownloader.figshare.com/files/6453753`，MD5 为 `07f004eca867447d69c71e87be242d75`，脚本会验证。原始文件放在被 Git 忽略的 `backend/uploads/public-data/`；本机已下载。仅在需要导入新的本地案例时添加 `--import-local`。
